# MinerU Batch 设计文档

- 日期：2026-09-08
- 状态：已与需求方确认总体设计，待评审本文件

## 1. 目标

一个 Windows 桌面小工具：拖入文件或文件夹，自动调用 MinerU 精准解析 API，产出与源文件同名的 full Markdown（只要 `full.md`，不要图片等附属产物）。

成功标准：

1. 拖入单个文件 → 在源文件同目录生成 `<源文件名>.md`。
2. 拖入文件夹 → 在 `<用户文档目录>\MinerU\<文件夹名>\` 下生成同名 Markdown，子目录结构原样保留；不支持的文件自动跳过。
3. PDF 超过 200 页 → 自动按 ≤200 页分段转换后按顺序拼成单个 Markdown。
4. 打包成单个 `.exe`，**接收方无需安装 Python 或任何环境**，粘贴自己的 API Key 即可使用。
5. 界面简洁、深色科技感（深色底 + 青色光效）。

## 2. 用户场景

- 主要使用者：需求方本人（技术小白，要求操作极简）。
- 分发对象：任意 Windows 用户（近期目标）。对方在 https://mineru.net/apiManage 自行申请 Key，粘贴进程序即用。
- 单文件与批量（整文件夹）使用频率都高；>200 页大文件（如招股书、年报）是明确场景。

## 3. 非目标（本期明确不做）

以下需求已记录但本期不实现，见第 10 节延期特性清单。

## 4. 总体架构

程序 = **界面层（PySide6）** + **转换引擎（Python 内置代码，1:1 移植 skill 逻辑）**。

```
拖拽 → 文件收集(递归/过滤) → 任务队列(顺序执行)
                                    │
                              转换引擎(后台线程)
                                ├─ ≤200页/非PDF: 单任务流程
                                └─ PDF>200页: 分段→逐段转换→拼接
                                    │
                              输出 full.md ← 仅抽取 ZIP 内 full.md
```

关键决策：**不依赖外部 MinerU skill 安装**。skill 源码仅作为移植参考，所有调用逻辑内置在程序里，理由是分发目标（对方机器上没有 skill）。程序不调用 `mineru.py`/`mineru_chunked.py` 子进程，不使用 `~/.qoder*` 下的任何配置。

## 5. 详细设计

### 5.1 界面（深色 + 青色光效）

主窗口（固定尺寸、不可最大化，保持"小工具"感）：

- 顶部：程序名 "MinerU Batch" + 右侧齿轮（设置）。
- 中部：拖拽区。虚线发光边框（青色），默认文案"把文件或文件夹拖到这里"；拖拽悬停时边框高亮。也支持点击弹出文件选择对话框（备选入口）。
- 下部：任务列表。每行：文件名 | 状态 | 输出位置（过长省略）。状态含：排队中 / 转换中（显示第 x/N 段或已等待时长）/ 完成 / 失败（原因摘要，行标红）。
- 底部：总进度条 + 汇总文案"全部完成：成功 X 个，失败 Y 个"。

首次启动无 Key：弹出设置对话框（模态），一句话引导 + 申请链接 + 输入框。

### 5.2 文件收集与输出规则

支持格式（后缀名过滤，大小写不敏感）：

`.pdf .doc .docx .ppt .pptx .xls .xlsx .png .jpg .jpeg .bmp .webp .html .htm`

- 拖入单个文件：输出到**源文件所在目录**，文件名 = `<源文件主名>.md`（如 `年报.pdf` → `年报.md`）。
- 拖入文件夹：递归收集全部受支持文件；输出根目录 = `<用户文档目录>\MinerU\<拖入文件夹名>\`；**相对子目录结构原样镜像**。其余文件类型静默跳过。
- 同名输出**自动覆盖**（重拖同一文件 = 重新转换）。
- 已知边界：同一目录下主名相同、仅扩展名不同的两个文件（如 `a.pdf` 与 `a.docx`）会都写成 `a.md`，后者覆盖前者。本期检测到此情况时在任务列表给出提示，不阻断。

### 5.3 转换引擎

对 skill 的 1:1 行为移植。API 契约（源自 skill 源码，基址 `https://mineru.net/api/v4`）：

单文件流程（非 PDF 或 ≤200 页 PDF）：

1. 本地预检：文件 >200MB → 直接报错（MinerU 在线上限）。
2. `POST /file-urls/batch`，payload：`{model_version:"vlm", enable_formula:true, enable_table:true, language:"ch", files:[{name, is_ocr:false, data_id:源文件主名, page_ranges?}]}`。
3. 从响应取 `data.batch_id` 与 `data.file_urls[0]`，`PUT` 上传文件（8MB 分块流式，超时 300s）。
4. 轮询 `GET /extract-results/batch/{batch_id}`：初始间隔 2s、×1.5 退避、上限 15s；`extract_result[]` 全部 `state=="done"` 为成功，全部 `failed` 为失败；单任务轮询超时 1800s。
5. 取 `record.full_zip_url` 下载 ZIP 到临时文件，仅抽取 ZIP 内以 `full.md` 或 `full_markdown.md` 结尾的条目写入输出；其余条目（图片等）一律不落地。删除临时 ZIP。

大 PDF 流程（>200 页）：

1. 用 pypdf 统计页数（读取失败按"文件损坏或加密"报错）。
2. 切成连续分段：`[(1,200),(201,400),…]`。
3. **顺序**逐段走上面的单文件流程，每段传 `page_ranges:"s-e"`，并把该段的**输出主名**设为 `<主名>.partN`（对应 skill 的 `--filename` 参数），段产物 = `<主名>.partN.md`，放在最终输出同目录。
4. 全部分段完成后按序拼接（段间插入两个换行），写最终 `<主名>.md`，删除各分段文件。
5. 某段失败：已完成的 `.partN.md` 保留在输出目录；之后**无论是同一任务重试还是重新拖入同一文件，都自动跳过已完成分段、只续转剩余分段**（断点续跑），全部完成后照常覆盖写出最终 md 并清理分段文件。由于成功的转换不会留下分段文件，已完成的文件重拖 = 完整重转 + 覆盖，与同名覆盖策略不冲突。

进度上报：分段任务报告"第 x/N 段"；单文件任务用不确定进度条 + 已等待时长，不伪造百分比。

### 5.4 API Key 管理

- 设置对话框：密码样式输入框（可切换明文查看）、保存、删除、"去 mineru.net 申请"按钮（打开 https://mineru.net/apiManage）。
- 存储：`<APPDATA>\MinerUBatch\config.json`，字段 `api_key`（仅本机当前用户可读）。
- 界面任何位置只显示掩码（如前 4 位 + 星号）；日志、错误信息、任务列表均不出现完整 Key。
- 启动时无 Key → 弹设置对话框；保存后进入主界面。

### 5.5 并发与队列

- 严格**单并发**：队列内逐个转换。原因：保护用户 API 配额与接口频率限制（skill 原生约束），且 MinerU 单任务本身耗时较长。
- 后台线程执行（Qt 信号与界面通信），界面全程可交互；提供"清空已完成"按钮。

### 5.6 错误处理（大白话文案，不甩错误码）

| 情况 | 界面行为 |
|---|---|
| Key 无效 / 过期（HTTP 401/403，code A0202/A0211） | "Key 失效了，请去 mineru.net 重新生成后在设置里更换"，行标红 |
| 每日任务额度用完（code -60018） | "今天的转换额度用完了，明天再试或升级套餐" |
| 文件 >200MB（code -60005 或本地预检） | "这个文件超过 200MB，在线版处理不了" |
| 页数 >200 时未走分段（code -60006，异常路径） | 按 bug 处理，提示重试 |
| 网络异常 / 超时 | "网络好像断了，已保留进度，重拖同一文件会跳过已完成分段"；单文件任务重试 |
| 其他业务错误 | 显示 API 返回的一句话原因 + 行标红，**不影响队列后续任务** |

单个文件失败不阻塞队列；全部结束后底部汇总成功/失败数。

## 6. 打包分发

- PyInstaller 打包为**单文件 .exe**（`--onefile --windowed`，内置 Python 运行时与全部依赖）。
- 仅在 Windows 10/11 验证；接收方零安装。
- 首次实机测试通过后再对外分发。

## 7. 技术栈与项目结构

- 语言：Python 3.11+；GUI：PySide6；HTTP：requests；页数统计：pypdf。
- 开发依赖：pytest（单元测试）；打包：pyinstaller。

```
MinerU Batch/
  app/
    main.py                  # 入口
    core/config.py           # Key 存取（APPDATA）
    core/collect.py          # 拖拽目标解析、递归收集、输出路径映射
    engine/client.py         # MinerU API 客户端（任务/上传/轮询/下载）
    engine/convert.py        # 单文件流程 + 分段编排 + 拼接
    ui/main_window.py        # 主窗口/任务列表/拖拽区
    ui/settings_dialog.py    # Key 设置
  tests/                     # pytest：路径映射、分段计算、ZIP 抽取、Key 存取、错误映射
  packaging/                 # PyInstaller spec + 构建脚本
  requirements.txt
  docs/superpowers/specs/    # 本文件
```

## 8. 测试策略

- 单元测试（HTTP 层打桩，不消耗真实配额）：
  - 输出路径映射（单文件/文件夹镜像/同名冲突提示）
  - 分段计算（199/200/201/601 页 → 分段区间正确）
  - ZIP 抽取（构造含 full.md 与图片的 ZIP，验证只落 md）
  - Key 存取与掩码显示、错误码 → 文案映射
- 端到端实测（消耗少量真实配额，开发机上跑）：
  - 普通 PDF（<200 页）→ 同目录 md
  - 一个 >200 页大 PDF → 分段拼接，人工抽查分段边界页（如 200/201 页）无重复无大段缺失
  - Word / 图片各一
  - 打包后的 .exe 在干净环境（无 Python）跑通

## 9. 已知限制（本期接受）

1. 跨分段边界的表格/段落会被切成两半（MinerU 分页机制的固有边界，skill 同样存在）；建议对关键文档抽查边界页。
2. 单个文件 >200MB 无法处理（MinerU 在线 API 上限）。
3. 受每日任务配额限制（-60018）。
4. 产出的 Markdown 中可能引用本地不存在的图片路径（因为不下载图片），属预期行为。
5. 仅 Windows；仅精准解析 API，不走 quick-parse（与 skill 的 Guardrails 一致）。

## 10. 延期特性（已记录，本期不做）

以下由需求方确认延后，按大致优先级排列：

1. **多文件并发转换**（当前严格单并发）。
2. **转换选项**：OCR 开关、公式/表格开关、语言、模型版本（当前固定 vlm / ch / 默认开关，与 skill 默认一致）。
3. **转换历史记录**（持久化已完成任务，重启后可查）。
4. **断网自动重试策略**（当前失败即停，靠手动重拖）。
5. **macOS / Linux 支持**。
6. **完整产物输出选项**（保留图片等附属文件，当前只保留 full.md）。
7. **调度员模式**：改回调用本机 MinerU skill 脚本（若未来分发需求消失、希望自动跟随 skill 升级）。
